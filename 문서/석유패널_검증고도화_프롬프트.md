# 「석유 산업의 분절화와 재연결(검증용)」 패널 신설 프롬프트
> 2026-10-15. Claude Code에 그대로 붙여 넣는다. 한 번에 끝까지(빌드→배포) 간다.

## 목표
기존 `bloc.html`은 **건드리지 않고**, 새 패널 **`site/oil_verify.html` — "석유 산업의 분절화와 재연결(검증용)"**을 하나 추가한다.
이 페이지는 "분절화와 재연결"이라는 제목이 **HS 2709·2710·2711 무역 데이터(2010~2026)로 증명되는지**를 그래프로 보여주는 검증 보고서다. 글 → 그래프 → 판정이 한 묶음으로 자연스럽게 이어져야 한다.
데이터는 `site/oil_trade.json`(`build_oil_data.py` 산출)을 그대로 쓴다. 그래프는 다른 패널처럼 **인라인 SVG**, 외부 CDN 없음.

## 만드는 법
1. `oil_verify_site.py` 신설. `bloc_site.py`의 `HTML` 스타일·헤더·`esc()`를 재사용하고 `build(out)` 함수를 둔다.
2. `publish_site.py`에 `oil_verify_site.build(out)` 호출과 index 카드(`<a href="oil_verify.html">석유 산업의 분절화와 재연결(검증용)</a>`)를 **bloc 카드 바로 아래**에 추가.
3. `python publish_site.py` → `deploy_site.ps1`로 배포. 배포 URL에서 실제로 열리는지 확인.
4. 다른 패널(solar/semi/ip_risk/bloc)의 html/json 해시가 빌드 전후 같아야 한다.

## 페이지 구성 (위에서 아래로)
**0. 데이터 신뢰도 — 짧게.** 미러 통계 설명 한 단락 + 작은 그래프 하나: 러시아·이란의 자체 신고가 '22/'14 이후 0으로 꺼지는 모습(수출국 신고 vs 상대국 신고 두 선). 이 페이지의 모든 그래프가 **수입국 신고**를 기본으로 쓰는 이유가 여기서 설명된다.

**1~5. 명제 다섯 개. 각각 = 한 줄 명제 → 그래프 → 판정(성립/불성립/판정불가) → 두 줄 해석.**
① 분절화: EU←RUS 2709·2710 수입, 2010~2026. '21→'23 급감이 보이는가.
② 재연결: RUS→IND·CHN·TUR 2709, 같은 축. ①의 감소분이 어디로 갔나 — ①과 ②는 **같은 그래프에 겹쳐** 그려 "흘러간" 모습이 보이게.
③ 2차 경로: IND→EU 2710(정제품). 러시아 원유가 인도 정제소를 거쳐 되돌아오는가.
④ 이란: CHN←MYS 2709 vs CHN←IRN 2709. 이란 직수입이 사라지고 말레이시아가 그만큼 뛰는가(환적 지표).
⑤ 2026 이란 분쟁: 걸프(SAU·ARE·IRQ·KWT·QAT)→동아시아(CHN·JPN·KOR·IND) 2709·2711, '25 상반기 vs '26 상반기 비교. 반쪽 데이터라 판정불가면 그렇게 쓰고 그래프는 그래도 둔다.
각 그래프에 **수출국 신고선을 옅게 같이** 그려 괴리를 숨기지 않는다. '22년 금액 급등은 유가 효과가 섞였다는 주의를 ②에 한 줄 단다.

**6. 종합.** 다섯 판정을 표 하나로. "제목이 데이터로 뒷받침되는 부분 / 안 되는 부분 / 데이터 한계로 말할 수 없는 부분" 세 줄.

**7. 부록 — 기준선 숫자.** 행 수, 국가 수, 매핑 실패 행 수(상위 코드 10개), 수집일(하드코딩 말고 원자료 mtime), 클럽 분류 두 구현(`build_blocs` vs `build_blocs_by_iso3`) 전 국가 diff 결과. 불일치가 있으면 여기 표로 노출만 하고 **고치지 않는다**.
