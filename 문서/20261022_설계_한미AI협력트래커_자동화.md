# 한미 AI 협력 트래커 자동화 설계

## 핵심 판단

- 자동화할 것은 세 단계다. (1) 후보 기사 탐지, (2) 기사에서 사건 추출·코딩, (3) 집계·화면·배포. 전부 `pipeline.yml` 안에서 매일 1회 돈다.
- 사람 손은 "고치고 싶을 때"만 든다. 저장소의 덮어쓰기 파일 한 줄로 어느 사건이든 수정·삭제·확정할 수 있다. 검수 없이도 게시되지만, 화면과 JSON 에 "자동 코딩"임을 항상 표시한다.
- 이 설계는 폴더 규칙("모델 예측을 확정 라벨로 표현하지 않는다")과 로드맵의 "확정 코딩은 연구자 판단"을 바꾸는 것이 아니라, 확정과 자동을 구분해 표시하는 방식으로 지킨다.

## 분석 단위와 스키마

- 단위: 사건(event) 하나. 같은 거래의 MOU → 확정계약 → 집행은 각각 사건이고 `prior_event_id` 로 잇는다.
- 저장 필드

| 필드 | 값 | 출처 |
|---|---|---|
| `id` | `YYYYMMDD-<해시8>` | 생성 |
| `date` | 발표일 | 기사 |
| `us_parties`, `kr_parties` | 정규화된 기관명 목록 | 모델 추출 + 기관 마스터 |
| `track` | 정부 / 민간 / 정부-민간 | 모델 |
| `form` | MOU·의향 / 선언 / 집행 / 확정계약 | 모델 |
| `sectors` | AI데이터센터 / 피지컬AI·로봇 / 통상·규제 / 파운드리 / 반도체 / AI모델·SW / 안보·국방 | 모델, 복수 |
| `title`, `summary` | 한 줄 제목, 2~3문장 요약 | 모델 |
| `amount_usd_bn` | 억 달러, 명시된 경우만. 추정치면 `amount_is_estimate=true` | 모델 |
| `sources[]` | URL, 매체, 등급(1차: 정부·공시·보도자료 / 2차: 언론) | 탐지 |
| `administration` | 오바마 / 트럼프 1기 / 바이든 / 트럼프 2기 | 날짜로 계산 |
| `status` | `auto` / `confirmed` / `rejected` | 기본 `auto`, 덮어쓰기로 변경 |
| `confidence` | 모델이 낸 0~1 | 모델 |
| `coded_by`, `coded_at`, `model` | 재현용 | 생성 |

- 기관 마스터 `reference/ai_coop_orgs.csv`: 표기 통일(엔비디아 = NVIDIA), 국적, 정부/민간, 업종. 모델이 새 기관명을 내면 `pending` 으로 붙이고 리포트에 알린다.

## 파이프라인

```
[1 탐지]  RSS·검색 → 후보 URL (매일)        collect_ai_coop.py discover
[2 본문]  URL → 본문 텍스트 (trafilatura)   collect_ai_coop.py fetch
[3 코딩]  본문 → 사건 JSON (Claude API)     collect_ai_coop.py code
[4 병합]  중복 제거·선행 사건 연결·덮어쓰기 적용
[5 게시]  ai_coop_events.json → Release 자산 → ai_coop_site.py build → Pages
```

### 1. 탐지

- 1차 출처(RSS 있음): 과기정통부·산업부·외교부 보도자료, White House, Commerce/BIS, State, DoD. 기업 뉴스룸: 삼성전자·SK하이닉스·SK텔레콤·현대차·LG전자·네이버·카카오 / NVIDIA·Microsoft·Google·AWS·OpenAI·Anthropic·Intel·Qualcomm·IBM·Meta.
- 보조: Google News RSS 쿼리 20~30개("Korea AI", "한미 AI", 기업명 쌍 등). 연합뉴스·전자신문 영문판 RSS.
- 1차 필터(모델 호출 전, 비용 0): 제목·요약에 한국 측 기관명과 미국 측 기관명이 각각 하나 이상 있고, AI·반도체·데이터센터·로봇 키워드가 있는 것만 통과. 이미 본 URL 과 제목 유사도 0.9 이상은 제외.
- 예상량: 후보 하루 100~300건 → 필터 후 10~40건.

### 2. 본문 — 유료벽 3단계 (연구자 결정 2026-10-22)

1. 원문 URL 의 본문(브라우저 UA 직접 요청, 차단되면 Wayback Machine 스냅숏).
2. 300자 미만이면 같은 사건을 다룬 다른 무료 출처를 찾는다. Google News RSS(사건일 ±21일 필터, 리다이렉트 링크 복호화)와 Bing News RSS. 보도자료·정부 문서(1차 출처)가 있으면 그것을 우선하고, 없으면 가장 긴 본문. 유료벽 도메인(WSJ·FT·Bloomberg·NYT·Reuters 등)은 후보에서 뺀다.
3. 그래도 없으면 제목(+RSS 요약)만으로 코딩한다. 모델에 그 사실을 알리고 confidence 상한 0.5, `body_missing=true` 로 화면에 "출처 보강 필요" 표시.

재현성(연구자 결정 2026-10-22): 코딩에 쓴 입력 원문을 그대로 기록한다. 실행 아티팩트의 `ai_coop_*_inputs.jsonl` 에 전문, 공개 결과(JSON)에는 URL·수집 경로(direct/wayback/alternative)·글자 수·SHA-256·앞 500자. 언론 기사 전문을 공개 저장소에 올리지 않기 위한 분리이며, 해시로 전문의 동일성을 검증할 수 있다.

### 3. 코딩 (LLM)

- 모델: `claude-opus-5-5` 기본. 구조화 출력(`output_config.format`)으로 스키마를 강제하고, 효과 `medium`. 한미 양쪽 주체가 본문에서 확인되지 않으면 사건으로 만들지 않는다(`is_event=false`).
- 한 호출에 기사 하나. 시스템 프롬프트에 코딩 규칙(형태 4분류의 판정 기준, 분야 정의, 금액 처리 규칙)과 예시 사건 10건을 고정해 넣고 프롬프트 캐시를 켠다.
- 같은 사건을 여러 기사가 다루면 기사별 결과를 모델이 아니라 코드가 접는다(날짜 ±3일, 주체 집합 일치, 제목 유사도).
- 비용 추정(기사 1건 입력 3천 토큰, 출력 400토큰, 하루 30건): Opus 5.5 기준 입력 $0.36 + 출력 $0.24 = 약 $0.6/일, 월 약 $18. Sonnet 5.5 면 절반, Haiku 5.5 면 월 $1 미만. 정확도 요구가 높은 형태 판정 때문에 Opus 를 기본으로 두되 연구자가 바꿀 수 있다.
- 초기 표본 재코딩: 노션에서 내보낸 수십 건을 같은 프롬프트로 다시 코딩해 사람 코딩과 일치율을 잰다. 이것이 첫 번째 정확도 측정이고, 불일치 사례가 프롬프트의 예시가 된다.

### 4. 병합과 덮어쓰기

- `data/ai_coop_overrides.csv`(git 추적): `id, field, value, note, date`. 연구자가 GitHub 웹에서 한 줄 추가하면 다음 실행부터 반영. `field=status, value=rejected` 면 화면에서 뺀다. `status=confirmed` 면 "확정" 표시.
- 선행 사건 연결: 주체 집합이 겹치고 형태가 진행 방향(MOU→선언→집행→확정계약)이면 후보로 묶고 `prior_event_id` 에 적는다. 모델이 아니라 규칙.
- 기관 마스터에 없는 이름은 `pending` 으로 두고 주간 요약에 목록을 낸다.

### 5. 게시

- 산출 `ai_coop_events.json` 은 Release `state` 자산. 매일 덮어쓴다. 화면은 지금 `ai_coop_site.py` 가 그리는 것(타임라인·형태별 비중·주체 조합·분야×형태 매트릭스·목록)을 그대로 쓰되, 행마다 `status` 배지와 출처 등급을 보인다.
- 추가 화면: 확정계약 누적 금액(명시 금액만, 추정치는 점선), "최근 7일 새 사건" 섹션.

## Task A 와 Task B

- **Task A — 신규 사건 코딩.** 새 기사에서 사건 하나를 추출한다(위 3절). 입력은 기사 하나.
- **Task B — 기존 사건 갱신.** 이미 등록된 사건마다 후속 상황을 쫓는다. 입력은 기존 사건 레코드 + 새 기사. 표본의 비고가 요구하는 일이 바로 이것이다(오로라 지분 매각, 테슬라 계약 상향 가능성, SK텔레콤 추가 매수, 테일러 팹 일정 지연).

### Task B 의 판정

기사 하나와 관련 사건 레코드(주체가 겹치는 기존 사건 1~3건)를 함께 주고, 모델은 관계를 하나 고른다.

| 관계 | 뜻 | 코드가 하는 일 |
|---|---|---|
| `unrelated` | 다른 사건 | Task A 로 넘긴다 |
| `same_event` | 같은 사건의 추가 보도 | 출처만 추가. 1차 출처면 등급 상향 |
| `follow_up` | 같은 거래의 다음 단계(MOU→확정계약→집행) | 새 사건 생성, `prior_event_id` 연결 |
| `correction` | 기존 사건의 사실이 바뀜(금액·날짜·주체·형태) | `updates[]` 에 필드·이전값·새값·근거 기록 |
| `lifecycle` | 완료·취소·지연·규모 변경·관계 종료 | `lifecycle` 필드 갱신 + `updates[]` 기록 |

- `lifecycle` 값: announced → in_progress → completed / cancelled / delayed / superseded. 형태(form)는 발표 시점의 성격이므로 바꾸지 않고, 진행 상태는 이 필드가 맡는다.
- 적용 규칙: `status=auto` 사건은 자동 적용. `status=confirmed` 사건은 `updates[]` 에 "보류" 로 쌓고 화면과 주간 요약에 보여 연구자가 덮어쓰기 파일로 승인한다. 확정 코딩을 모델이 뒤집지 않는다.

### Task B 의 탐지

- 사건마다 질의를 만든다: 주체 쌍 + 핵심어(계약·인수·양산·착공·완료·취소·매각·지연) + 사건일 이후. Google News RSS 와 기업 뉴스룸 검색.
- 주기: `lifecycle` 이 announced·in_progress 인 사건은 매주, completed 는 월 1회, cancelled·superseded 는 중단. 사건일로부터 3년이 지나면 월 1회로 내린다.
- 예상량: 열린 사건 30~40건 × 주 2~5건 후보 → 주 100~150건 모델 호출. Task A 와 같은 모델·프롬프트 캐시를 쓰며 월 비용은 Task A 와 비슷하다.

### 흐름의 통합

```
후보 기사 ──▶ 주체·날짜로 관련 기존 사건 검색 ──┬─ 있음 ──▶ Task B (관계 판정·갱신 추출)
                                                 └─ 없음 ──▶ Task A (신규 사건 코딩)
```
- Task A 가 만든 사건도 다음 실행부터 Task B 의 감시 대상이 된다.
- 최초 1회 소급 실행: 표본 47건 각각에 대해 사건일 이후 기사를 검색해 후속 사건·종료·수정을 채운다. 비고에 적힌 "별도 확인 대상" 항목들이 이 실행에서 해소되는지가 Task B 의 첫 검증이다.

### Task B 프롬프트의 골자

- 시스템: Task A 와 같은 정의·규칙 + 관계 5종의 정의 + "기존 레코드의 값을 바꾸려면 기사에 명시된 근거 문장을 evidence 에 그대로 인용한다" 규칙.
- 사용자: 기존 사건 JSON(1~3건) + 기사. 출력: `{relation, target_event_id, new_event?, updates[], lifecycle?, evidence, confidence}`.

### 화면에 추가되는 것

- 사건 행의 진행 상태 배지(announced/in_progress/completed/cancelled/delayed)와 "최근 갱신" 표시.
- 연결된 사건 묶음(MOU → 계약 → 집행)을 타임라인에서 선으로 잇기.
- 전환 지표: MOU·선언 중 N개월 안에 확정계약·집행으로 이어진 비율(분모 = 사건일로부터 N개월이 지난 MOU·선언 수).
- 보류 중 갱신 목록(확정 사건에 대한 모델 제안).

## 첫 실측 — 표본 47건 재코딩 (2026-10-22, Opus 5.5, effort high, 프롬프트 v1)

- 입력 확보: 본문 46건(원문 직접 36, Wayback 5, 대체 출처 3, 기타), 제목만 1건(IBM 2020). 47건 전부 코딩. 호출 47회, 11분, 비용 $1.55(사건당 3.3센트 — 사고 토큰 5.2만이 비용의 2/3).
- 보류 표본 37건(프롬프트 예시 10건 제외) 일치율: form 65%, track 89%, 분야 Jaccard 0.66, 미국 주체 0.57, 한국 주체 0.60, 금액 84%, 날짜 86%, 사건 인정 95%. 예시 10건은 form 100%(암기).
- form 불일치 12건의 패턴
  1. "인수 완료·지분 취득 완료"를 연구자는 집행, 모델은 확정계약으로(하만, 보스턴다이내믹스). 규칙 보강 필요.
  2. 공식 파트너십·협력 발표를 연구자는 확정계약, 모델은 "조건 비공개 → 더 약한 쪽" 규칙에 따라 MOU로(SDC19, POWER10, KT–MS, 볼리). 연구자 기준이 "계약 체결이 명시되면 금액 없어도 확정계약"이라면 규칙을 바꿔야 한다.
  3. 한 기사가 여러 거래를 묶어 보도(샌프란시스코 서밋·네이버·GPU 26만장)하면 모델이 우산 사건 하나로 코딩. 기사당 사건 여러 개를 내도록 출력을 배열로 바꿔야 한다.
  4. 범위 판단: 하만 인수를 AI 범위 밖(is_event=false)으로 봄. 자율주행·전장을 범위에 명시해야 한다.
- 주체 불일치는 대부분 표기 차이(Intel/인텔, Microsoft/MS, 현대차그룹/현대차·기아·현대모비스, 백악관 OSTP/백악관). 기관 마스터와 정규화로 해결. 묶음 기사에서는 모델이 기사 속 모든 기관을 나열해 과대.
- 금액 불일치 8건: 모델은 거래금액만(기업가치·패키지 총액·원화 환산 제외), 연구자 규모 열은 기업가치(보스턴 11)·국내 보도 환산액(KT 18)·패키지(네이버 100)를 포함. 의미를 정해야 한다.
- track 불일치 4건: 정부–기업 조합을 연구자는 사건마다 다르게(과기정통부–오픈AI=정부, AWS–정부(한국)=민간, 과기정통부·현대차–엔비디아=정부-민간). 규칙이 명문화돼 있지 않다.
- 결론: 입력 확보와 호출은 안정적. 정확도는 프롬프트 규칙 3개(집행 정의, 확정계약 기준, 다중 사건)와 기관 마스터로 올릴 여지가 크며, 금액·track 은 연구자의 기준 확정이 먼저다.

## 연구자 결정 (2026-10-22, 첫 실측 뒤) — 프롬프트 v2 에 반영

1. 금액 = 거래금액만. 기업가치·패키지 총액·투자 계획 총액은 note 로.
2. track = 정부-정부 / 정부-민간 / 민간-민간. 양측 당사자의 성격으로 기계적으로 계산한다(기관 마스터의 type). 시드의 옛 track 은 `track_original` 로 보존.
3. 확정계약 기준 = 문서의 법적 성격. 구속력 있는 문서(계약 체결·인수·지분 취득·합작·장기 공급·라이선스·협약 체결)가 명시되면 금액이 없어도 확정계약. 비구속 문서(MOU·LOI·업무협약)나 문서가 특정되지 않은 발표는 MOU·의향. 앞선 구속력 거래의 이행·완료(인수 완료·양산·출시)는 집행.
- 함께 바꾼 것: 기사 하나에 사건 여러 개(events 배열), 자율주행·전장을 범위에 명시, 기관 표기 마스터 `reference/ai_coop_orgs.csv`(표준 표기·별칭·국적·정부/민간)를 프롬프트와 정규화에 사용.

## 운영 방식 확정 (2026-10-22, 연구자 결정) — 판단 요청과 결정 회수

- AI 는 아무것도 직접 반영하지 않는다. 매일 06:00 KST 실행이 A(새 사건 후보)·B(기존 사건 갱신 후보)·C(기존 판단 재검토) 제안을 만들어 사이트 `review.html`(판단 대기)에 올리고, 랜딩에 대기 건수 배너를 띄운다. GitHub Issue 로 보내는 안은 연구자가 거부했다.
- 결정 입력은 페이지에서 한다. 카드마다 승인·기각·보류(객관식)와 의견·수정 지시(주관식). 입력은 브라우저에 임시 저장되고, "GitHub으로 결정 제출" 을 누르면 결정이 미리 채워진 GitHub Issue 작성 화면(라벨 `ai-coop-decision`)이 열려 버튼 한 번으로 제출된다. 토큰·설치 불필요. 대안으로 `data/ai_coop_decisions.csv` 직접 편집.
- 다음 실행의 `apply` 가 Issue 본문(저장소 소유자·협력자 것만)과 CSV 를 읽어 반영한다. 승인은 그대로, 의견에 수정 지시가 있으면 Task D(모델이 의견대로 값을 고침, 연구자 의견 우선)를 거쳐 반영하고 `updates` 에 "연구자 의견"으로 근거를 남긴다. 기각은 기록, 보류는 다음 날에도 남는다. 처리한 Issue 는 결과 댓글을 달고 닫는다.
- 같은 거래를 다룬 여러 기사는 제안 하나로 묶는다(주체 Jaccard ≥ 0.5, 날짜 ±3일). 나머지 기사는 "다른 기사" 목록으로 붙인다.
- 화면 글자는 전부 20pt 이상(연구자 지시).
