# 자동 업데이트 산출자료 코드북

`auto_update.py` 가 만드는 GTA 스냅숏(`cache/master.parquet`, Release `state`)의 열 정의다. 2026-10-22부터 엑셀은 만들지 않는다. 아래 "분석용 23열"과 "뺀 11열"은 모두 `master.parquet` 에 들어 있다. 기존 JLOP 공개자료의 코드북이 아니다 — **자료 원천도 열 구성도 기존 JLOP와 다르다**(아래 "기존 JLOP 공개자료와 어긋난다" 참조). 사이트 `codebook.html` 이 이 파일을 그대로 보여 준다.

- 분석 단위: GTA intervention
- 식별자: `intervention_id`
- 자료 기간: 2010-01-01 ~ 자료 기준일
- 자료 출처: GTA API v2 `POST /api/v2/gta/data/` (Full Access) 단독
- 이 문서 기준 스냅숏: **2026-08-10, 82,465건**

## 파일 2종

| 파일 | 열 | 용량 | 용도 |
|---|---:|---:|---|
| `JLOP_BERT_2010-YYYYMMDD_analysis.xlsx` | 23 | 약 13MB | 통계분석용 |
| `JLOP_BERT_2010-YYYYMMDD_full.xlsx` | 34 | 약 59MB | 원문 확인·재현·감사용 |

두 파일은 같은 표본·같은 정렬이다. 분석용은 전체의 부분집합이므로 `intervention_id`로 언제든 되붙일 수 있다.

정렬은 `date_announced` 오름차순, 동일 날짜 안에서는 `intervention_id` 순이다.

### `latest_action_name` · `latest_action_date` · `last_edited`은 서로 다른 것이다

이름이 비슷해 뭉뚱그리기 쉬운데 성격이 다르다. 2026-08-13 실측(82,599건).

| 열 | 무엇 | 성격 |
|---|---|---|
| `latest_action_name` | 이 조치에 마지막으로 일어난 사건의 **이름** | 조치 자체의 정보 |
| `latest_action_date` | 그 사건이 일어난 **날** | 조치 자체의 정보 |
| `last_edited` | GTA 연구자가 이 **기록**을 손본 날 | 자료 관리 메타데이터 |

`latest_action_name`의 값은 23종이다. `Announcement` 79,115건(95.8%)이 압도적인데, 이는 **발표된 뒤 아무 일도 일어나지 않았다**는 뜻이다. 나머지 3,484건이 실제로 단계가 움직인 건이다: `Prolongation - removal` 992 / `Removal` 790 / `Clarification` 289 / `Prolongation - implemented` 289 / `Inception` 175 / `Definitive duty` 159 / `Review` 122 / `Renewal` 111 / `Termination - announced` 108 / `Preliminary duty` 66 …

반덤핑 생애주기(조사 개시 → 예비관세 → 확정관세 → 재심 → 종료)가 이 열에 들어 있다. `date_removed`·`is_in_force`는 "없어졌나"만 알려주므로 **이 단계 정보는 여기에만 있다.** 반덤핑이나 조치 수명을 다룰 때는 전체판에서 가져와야 한다.

`latest_action_date`는 79,136건(95.8%)이 `date_announced`와 같다. 위 `Announcement` 비율과 일치한다.

## 해석상 주의

### 1. `date_published`를 정책 변수로 쓰지 마라

GTA의 기록 시점이지 정책의 시점이 아니다. 발표연도별 등재 시차 실측값이다.

| 발표연도 | 발표→등재 중앙값 |
|---|---:|
| 2010 | **9.9년** |
| 2013 | 6.2년 |
| 2016 | 3.6년 |
| 2018 | 0.8년 |
| 2021 | 0.8년 |
| 2023 | 0.2년 |
| 2025~26 | **9일** |

2010년대 초 자료는 GTA가 한참 뒤에 소급 입력했다. 쓸 데는 GTA 수집 편향 진단 하나뿐이다.

**게다가 최근 자료에는 값이 아예 없다.** 2026-08-10 스냅숏 기준 `date_published`의 최댓값은 **2026-06-23**으로 기준일보다 48일 뒤처져 있다.

| 발표월 | 건수 | `date_published` 있음 |
|---|---:|---:|
| 2026-05 | 627 | 526 (84%) |
| 2026-06 | 595 | 268 (45%) |
| 2026-07 | 608 | **0 (0%)** |
| 2026-08 | 34 | **0 (0%)** |

값이 비어 있어도 자료 자체는 GTA 웹사이트에 정상 공개되어 있다(`globaltradealert.org/intervention/156999`에서 확인). 결측은 공개 여부와 무관하다. 다만 **최근 2개월치를 이 열로 거르면 표본이 통째로 사라진다.**

정의와 실제 값이 어긋나는 부분도 있다. 스키마는 `update_period`를 설명하며 "수정 이력이 없으면 `last_updated`는 게시일과 같다"고 적었으나, 실제로는 `last_updated`가 `date_published`보다 앞서는 행이 대부분이다(2010년 건 기준 3,605일 앞섬). 두 값이 같은 개념이 아닐 가능성이 있으며 확정하려면 GTA에 문의해야 한다.

### 1-1. `last_updated`도 구간마다 성격이 다르다

`last_updated`에서 `date_announced`를 뺀 값의 분포다.

| 발표연도 | 정확히 0일 | 1~7일 | 8~30일 | 365일+ |
|---|---:|---:|---:|---:|
| 2010 | 99.5% | 0.0% | 0.0% | 0.5% |
| 2015 | 99.5% | 0.0% | 0.0% | 0.5% |
| 2022 | 99.2% | 0.0% | 0.1% | 0.7% |
| 2025 | 54.1% | 15.8% | 11.2% | 2.5% |
| 2026 | 12.7% | 36.9% | 31.5% | 0.0% |

2022년 이전 건은 정확히 0일이 99%인데 1~7일 구간이 0.0%다. 실제 입력 시각이라면 며칠에 걸쳐 퍼져야 하므로, 이 구간의 값은 **발표일이 복사된 것으로 보인다.** 2026년 건은 자연스럽게 퍼져 있어 진짜 타임스탬프다.

`365일+` 열은 GTA가 과거 건을 나중에 고치면 `last_updated`가 그때로 옮겨간다는 것을 보여준다(2024년 건의 14.4%). **기존 건의 개정 추적에는 쓸 수 있다.**

### 2. 2020년 건수 급증은 해석에 주의가 필요하다

```
2010~2019   연 3,469 ~ 3,954건
2020        7,717건   ← 약 2배
2021~2025   연 6,124 ~ 7,456건
```

코로나 대응 조치의 실제 급증과, GTA 수집 역량 확대가 겹쳐 있다. 위 등재 시차 표에서 2018년을 기점으로 시차가 급감하는 것이 후자의 방증이다. **산업정책 증가 추세를 주장할 때 반드시 구분해야 한다.**

### 3. `mast_chapter`에 접두어가 섞여 있다

17개 값 중 11개는 `L: `, `P: ` 같은 접두어가 있고, 6개는 없다. GTA 원자료가 그렇다.

```
접두어 있음   L: Subsidies (excl. export subsidies)      36,863
              P: Export-related measures (incl. subsidies) 13,518
접두어 없음   Tariff measures                            10,174
              FDI measures                                1,723
              Capital control measures                    1,377
              Migration measures                            661
              Instrument unclear                            532
```

접두어 없는 값이 **14,467건(17.5%)**이다. 이 프로그램은 GTA 원값을 그대로 보존하며 접두어를 떼지 않는다. 집계 전에 정규화할지는 연구자가 판단한다.

`F:  Price-control measures...`처럼 콜론 뒤 공백이 둘인 값도 있으니 문자열로 매칭할 때 주의한다.

### 4. 기존 JLOP 공개자료와 어긋난다

2010–2022 구간도 이 프로그램이 직접 분류한 결과다. 기존 JLOP 라벨과 다를 수 있다. 기존 코드북의 재현 검증 기록은 300건 중 296건 일치(0.9867)였다.

또한 GTA가 항목 이름을 바꿔 왔다. 기존 JLOP 파일은 `Subsidies (excluding export subsidies)`, 현행 GTA는 `Subsidies (excl. export subsidies)`다. **두 자료를 이어 붙이면 같은 범주가 둘로 갈라진다.** 대조가 필요하면 `../원자료/260718_BERT_Expansion/`의 원본을 쓰되 어휘 차이를 먼저 맞춘다.

### 5. `affected_products`(전체판) 354건이 잘려 있다

엑셀 셀 한계 32,767자를 넘어 잘린다. 최대 건은 HS 코드 125,311개(1,002,427자)를 32,767자로 잘라 96.7%가 사라진다.

**잘림은 이 열에서만 일어난다.** 2026-08-13 전수 확인: 초과 354건이 전부 `affected_products`였고 `intervention_description`은 최장 14,458자로 한계의 절반에도 못 미친다. 실행 화면의 "잘린 값 N개" 경고는 언제나 이 열 이야기다.

초과 건의 성격(실측):

| | |
|---|---|
| 품목코드 개수 중앙값 | **5,285개** (전체 건의 중앙값은 **1개**) |
| 최대 | 125,311개 |
| 조치 유형 | `Import tariff` 217 / `Export ban` 22 / `Import ban` 19 / `Internal taxation of imports` 17 |
| 시행 관할 | 미국 131 / 인도 26 / 일본 15 / 아르헨티나 14 / 튀르키예 13 |

**관세표를 통째로 건드리는 광범위 조치**다(미국 301조 관세, 인도 예산 관세개정 등). 품목을 하나하나 지정하니 목록이 폭발한다.

**HS 코드로 분석하려면 엑셀이 아니라 `cache/master.parquet`이나 API 원응답을 써야 한다.** 분석용 파일에는 이 열이 없으므로 해당 없다.

`affected_sectors`(CPC)는 건당 코드 수가 적어 한 건도 잘리지 않는다.

### 6. BERT 절단 2.3%

512토큰을 넘어 앞부분만 입력된 건이 **1,877건**(분류분 82,104건의 2.3%)이다. 2026-08-13부터 **분석용에도** `bert_was_truncated`가 들어가므로 분석용 파일만으로 걸러낼 수 있다.

512토큰은 BERT의 구조적 한계이지 이 프로그램의 결함이 아니다. 원 분류기를 만든 쪽도 같은 한계 아래 학습했을 것이므로 라벨은 그 연구 관행과 어긋나지 않는다. 글자로는 대략 1,300~2,000자부터 걸린다(실측 최단 절단 건 1,299자).

**어디에 몰려 있나**(실측):

| | 잘린 건 | 그 유형 전체 대비 |
|---|---:|---:|
| `Anti-dumping` | 350건 | **13.6%** |
| `Import tariff` | 274건 | 2.7% |
| `Minimum import price (tariff-based)` | 90건 | 7.6% |
| `Import tariff quota` | 88건 | 5.4% |
| 콜롬비아 | 77건 | **19.7%** |

반덤핑이 압도적이다. 제소 절차·기업명·품목·세율표를 나열해 길어진다(잘린 건 설명문 중앙값 2,853자 vs 안 잘린 건 991자).

**라벨 분포가 치우쳐 있다 — 원인은 미확인이다.**

| | 잘린 건 | 전체 |
|---|---:|---:|
| 산업정책 | 18% | 40% |
| 산업정책 아님 | **51%** | 18% |
| 목적 불명확 | 31% | 41% |

해석이 둘이다. (1) 정당한 결과 — 반덤핑은 무역구제이지 산업정책이 아니므로 `산업정책 아님`이 많은 게 맞다. 잘린 건의 19%가 반덤핑이니 이것으로 대부분 설명된다. (2) 절단이 만든 편향 — 긴 문서는 도입부가 법령 인용·절차라 정책 목적 문장이 뒤로 밀린다. (1)이 더 그럴듯하지만 검증하지 않았다. **반덤핑을 분석 대상으로 삼는다면 이 열로 제외해보고 결과가 흔들리는지 확인할 것.**

### 7. 분류 확신도가 낮은 건이 있다

전체판 `bert_max_probability` 기준이다.

```
평균 0.968   중앙값 0.998
0.9 미만   8,183건 ( 9.9%)
0.6 미만   1,561건 ( 1.9%)

```

3분류에서 0.5 미만은 사실상 판별이 안 된 것이다. 193건은 견고성 검사에서 빼보는 편이 낫다.

### 8. 스냅숏마다 과거 자료도 바뀐다

이 프로그램은 매 실행에서 2010년 이후 전 구간을 최신 GTA로 갱신한다. 지난달 파일과 이번달 파일의 2015년 자료가 다를 수 있다. 3.5주 간격 실측 변동폭이다.

| 변수 | 변동 |
|---|---:|
| BERT 라벨 | 0.21% |

## 잠수함 패치 가능성 목록

GTA가 **공지 없이 바꿀 수 있는 것들**이다. 바뀌어도 프로그램은 안 죽고 숫자만 조용히 달라지는 것이 대부분이라, 알아채는 방법을 같이 적어둔다.

아래 수치는 전부 2026-08-10 스냅숏 실측이다.

### A. 이미 일어난 것 — 재발 가능

**A-1. MAST 분류 명칭 변경** · 위험 높음

기존 JLOP 자료(2022년 이전 수집분)와 현행 GTA의 명칭이 다르다.

```
구:  Subsidies (excluding export subsidies)     20,312건
현:  Subsidies (excl. export subsidies)         10,494건
구:  Export-related measures
현:  Export-related measures (incl. subsidies)
구:  Intellectual property   →   현: Intellectual Property
```

17개 값 중 9개만 옛 이름과 겹쳤다. **전 기간을 `groupby`하면 최대 범주인 보조금이 두 줄로 쪼개진다.** 양쪽 숫자가 모두 그럴듯해서 눈으로는 못 잡는다.

- **알아채는 법**: 변경 리포트의 "수정된 항목별 건수"에 `mast_chapter`가 대량으로 뜬다
- **안 잡히면**: 시계열 집계가 특정 시점에서 갈라진다

**A-2. `intervention_type` 목록 변경** · 위험 중간

고유값 65종 → 71종, 교집합 59종. `Capital injection and equity stakes` → `Equity stake`, `Technical barrier to trade` 소멸, `Debt purchase`·`Export price benchmark` 신설.

- **주의**: 수출통제 9종 씨앗 목록이 여기 걸린다. `Local supply requirement for exports`가 표기 변경되면 씨앗 35건이 조용히 빠진다
**2026-08-11에 실제로 일어났다.**

```
Import price benchmark  →  Minimum import price (tariff-based)    1,187건
Minimum import price    →  Minimum import price (absolute floor)     16건

유형 개수는 76개 → 76개로 그대로였다
```

하루 사이에 벌어졌고, 개수가 같아서 눈으로는 잡히지 않는다. 다행히 수출통제 9종은 영향이 없었다(`Export price benchmark`는 수출 쪽, 바뀐 것은 수입 쪽).

- **알아채는 법**: 변경 리포트의 "바뀐 항목"에 `intervention_type`이 대량으로 뜬다
- **방어**: 이 프로그램은 매 실행마다 수출통제 9종 이름이 살아 있는지 확인하고, 0건이 되면 큰 경고를 띄운다. 다른 유형으로 표본을 고르는 분석 스크립트에도 같은 검사를 넣을 것

**A-3. `implementation_level` 표기** · 위험 낮음

`NFI`/`IFI`(대문자) ↔ `nfi`/`ifi`(소문자)로 갈린 이력이 있다. `Subnational`은 최근에 등장했다.

### B. 값이 나중에 채워지는 것 (처리 지연)

기다리면 채워진다. **매주 돌리면 채워지는 순간이 변경 리포트에 잡힌다.**

**B-1. `date_published` 등재일** · 위험 높음

```
최댓값 2026-06-23  (자료 기준일보다 48일 전)
2026-07 발표 608건 중 값 있음 0건 (0%)
2026-08 발표  34건 중 값 있음 0건 (0%)
2026-05 발표 627건 중 값 있음 526건 (84%)
```

값이 없어도 자료는 GTA 웹사이트에 정상 공개돼 있다(`intervention/156999`로 확인). 즉 **공개 여부와 무관한 내부 관리값**이다.

- **깨지는 것**: `submission_period` 필터, `lag_adjustment` 백테스트. 최근 2개월 구간에서 못 쓴다
- **대응**: 이 프로그램은 `submission_period`를 안 쓴다. 백테스트는 매주 쌓이는 실측 스냅숏으로 대체한다

**B-2. `is_in_force=0`인데 철회일 없음** · 위험 높음

```
전체 3,350건
수출통제 표본 786건 중 73건 (9.3%)

연도별:  2026년 24.3%  2025년 17.0%  2024년 1.6%  2023년 0.0%
```

GTA가 "유효하지 않음"을 먼저 표시하고 날짜는 나중에 채운다. 기울기가 가파른 것이 근거다.

- **깨지는 것**: 생존분석. `date_removed`만 보면 이 건들이 "생존"으로 잡힌다
- **대응**: 이벤트 정의를 `date_removed <= 오늘` **또는** `is_in_force == 0`으로 할 것
- **확인됨**: 2026-08-11 실행에서 `date_removed` 2건, `is_in_force` 3건이 실제로 갱신되어 변경 리포트에 잡혔다

**B-3. 최근 며칠 자료 없음** · 위험 낮음

`date_announced` 최댓값이 자료 기준일보다 4일 이르다. 매 실행 공통이다.

**B-4. 진행 중인 사건의 설명문이 통째로 다시 쓰인다** · 위험 높음

무역구제 사건(반덤핑·상계관세 등)은 단계가 있다.

```
조사 개시  →  잠정관세  →  확정관세  →  연장
```

**GTA는 단계가 넘어갈 때 새 행을 만들지 않는다. 기존 행의 설명문과 제목을 갈아끼운다.**

2026-08-11 실행에서 실제로 관측했다.

```
148473  어제 "EU: Provisional antidumping duty..."     → 오늘 "Definitive antidumping duty..."
151310  어제 "EU: Initiation of anti-dumping investigation..." → 오늘 "Provisional anti-dumping duty..."
71864   어제 "EU: Definitive countervailing duty..."   → 오늘 "Extension of definitive countervailing..."
```

- **BERT 라벨이 뒤집힌다.** 위 5건은 전부 `No IP goal` → `Not enough information`으로 갔다. 새 설명문이 짧은 절차 서술로 바뀌어 모델이 판단 근거를 잃은 것으로 보인다
- **확신도가 높아도 안 막아준다.** 뒤집힌 5건의 어제 확신도는 **전부 0.999**였다. `bert_max_probability`는 **그 시점의 판단이 확실하다는 뜻이지, 내일도 같을 거라는 뜻이 아니다**
- **설명문에서 뽑는 변수는 전부 영향을 받는다.** 정규식이든 분류기든 마찬가지다

**수명 분석에는 특히 위험하다.** 조치가 오래 살아남을수록 사건이 여러 단계를 거치고, 그만큼 설명문이 다시 쓰일 기회가 많아진다. **수명과 설명변수가 서로 상관되는 구조**라 그대로 쓰면 인과 해석이 깨진다.

- **알아채는 법**: 변경 리포트의 "BERT 라벨이 바뀐 건" 표에 설명문 길이 변화가 같이 적힌다. 크게 줄었으면 갈아끼운 것이다
- **대응**: 논문에 쓸 설명변수는 **발표 당시 스냅숏의 값**이어야 한다. 매주 파일을 남기면 그게 가능해진다

**C-1. 연도가 박힌 연간 목록이 영원히 "생존"** · 위험 높음

```
중국  절단 291건 중 10년 넘게 생존 표시 73건 (25.1%)
미국  절단 301건 중                    22건 ( 7.3%)

China: 2014 Tariff Implementation Plan released       4건

```

2012년 목록은 2013년 목록으로 대체된다. 14년이 지나도록 종료가 기록되지 않았다. **기다려도 안 채워진다.**

- **식별법**: `state_act_title`에 `20\d\d`가 있고 발표연도가 2017년 이전. 2019년 이후 발표건에는 이 패턴이 0%다
- **대응**: 손으로 처리하거나 제외하고 강건성 검사

### D. 값의 의미가 구간마다 다른 것

**D-1. `last_updated`가 구간마다 다른 값** · 위험 높음 (2026-08-28 정정: 아래 D-1-a 전까지는 "증분 수집에는 지장 없다"고 적었으나 틀렸다)

2022년 이전 건의 99%가 발표일과 **정확히** 일치하고 1~7일 구간이 0.0%다. 실제 수정 시각이 아니라 발표일이 복사된 값으로 보인다. 2026년 건은 정상(12.7%만 일치).

**다만 새로 등록되는 건에는 문제가 없다.** 2026-08-11 실행에서 2025-12-29·2026-04-21에 발표된 건들이 빠른 업데이트로 잡혔다. GTA가 오래된 조치를 새로 등록할 때 수정일을 **등록한 날**로 찍는다는 뜻이다. 발표일로 백데이트하지 않는다.

- **영향**: 과거 구간의 `last_updated`를 "마지막으로 손댄 날"로 해석하면 안 된다.

**D-1-a. `last_updated`는 GTA가 값을 고쳐도 안 바뀌는 경우가 훨씬 많다 — 증분 수집에 실질적 지장이 있다** · 위험 높음 · 2026-08-28 실측

08-24 전량 스냅숏과 08-27 전량 스냅숏(`output/SKL_Economic_Security_2008-20260824_full.xlsx`, `...20260827_full.xlsx`)을 `intervention_id` 기준으로 34개 컬럼 전부 직접 대조했다(코드의 `compare()`와 동일 로직, `CHANGE_IGNORE_COLUMNS`·라벨·신뢰도 컬럼만 제외).

```
신규 144 / 수정 386 / 삭제 3   (change_report_20260827_105304.md와 정확히 일치, 재현 검증됨)
```

이 386건 각각의 `last_updated`가 직전 점검일(08-24)~기준일(08-27) 구간에 들어오는지 확인:

```
last_updated가 그 구간 안에 있어 1번 모드(빠른 업데이트)로도 잡혔을 것   15건
last_updated가 안 바뀌어 1번 모드로는 절대 못 봤을 것                 371건
삭제 3건 (1번 모드는 삭제 여부를 아예 확인하지 않음)                    3건
──────────────────────────────────────────────
합계 389건 중 374건(96%)이 1번 모드로는 원천적으로 안 보였을 것
```

371건의 필드별 분포(중복 가능):

```
gta_evaluation             150   ← 최대. Red/Amber/Green 재평가
latest_action_name         117
affected_jurisdictions      63
intervention_description    44
state_act_source            33
is_in_force                 32
date_removed                15
affected_sectors            13
state_act_title              8
affected_products            7
date_implemented             3
inferred_jurisdictions       2
implementation_level         1
date_announced                1
```

87,381건 전체를 대상으로 `last_updated`(prev vs cur) 실제 변경 여부를 `latest_action_date`·`latest_action_name` 변경 여부와 교차했다:

```
                        latest_action_date 안바뀜   latest_action_date 바뀜
last_updated 안바뀜          87,333                        33
last_updated 바뀜                 0                        15

                        latest_action_name 안바뀜   latest_action_name 바뀜
last_updated 안바뀜          87,249                       117
last_updated 바뀜                 1                        14
```

`last_updated`가 바뀌면 `latest_action_date`는 항상 같이 바뀐다(15/15, 부분집합). 하지만 그 역은 전혀 성립하지 않는다 — `latest_action_name`이 바뀐 131건 중 117건(89%)은 `last_updated`가 그대로였다. 즉 "액션이 진행되면 last_updated도 갱신된다"는 규칙은 성립하지 않는다. 반례(ID 16154): `latest_action_name` Announcement→Renewal, `latest_action_date` 2011-09-23→2023-12-08(12년치 최신 사건이 붙음)인데도 `last_updated`는 2011-09-23에 그대로 얼어 있다.

- **원인 추정**: GTA 스키마 문서는 `update_period`를 "an update has been added to an intervention"이라고만 정의하고 무엇이 "update"인지 밝히지 않는다. 관찰된 패턴은 반덤핑류의 "공식 액션 단계 진행"(조사개시→잠정관세→확정관세)만 `last_updated`를 갱신하고, 애널리스트가 기존 레코드를 재평가·정정하는 것(`gta_evaluation` 재분류, `is_in_force`·`date_removed` 정정, 설명문·출처 교체)은 갱신하지 않는 것으로 보인다. GTA 내부 DB 설계 문제라 이 이상은 GTA에 직접 문의해야 확정된다.
- **영향**: `last_updated` 기반 증분 수집(1번 모드)은 위 371건 부류를 원천적으로 놓친다. 이건 버그가 아니라 GTA API의 구조적 한계다.

**D-1-b. GTA ticker 엔드포인트(`/api/v1/gta/ticker/`)도 이 문제를 해결하지 못한다** · 2026-08-28 실측, 가설 기각됨

quickstart 문서는 "poll the ticker, do not re-pull the corpus"를 권장 패턴으로 제시하고, ticker가 행 단위 `modified`·`status`(new/changed/static)를 준다는 점에서 `last_updated`보다 세밀할 것으로 기대했다. 직접 호출해서 검증했다.

- `update_period: ["2026-08-24","2026-08-28"]`로 ticker를 당겨 191건(`changed` 152, `new` 39) 확보 → 위 371건 목록과 **교집합 0건**.
- 371건 중 대표 사례(`131989`, `58567`, `88369`)를 ticker에 직접 조회 → 전부 `status: static`, 마지막 이벤트가 **2025-12-15**로 08-24~08-27 사이 실제 변경과 무관. `88369`는 `latest_action_name`이 08-24~08-27 사이에 바뀐 게 확인됐는데도 ticker에는 그 이벤트가 없다.

OpenAPI 스키마의 ticker 시리얼라이저 설명: *"description-centric format... Primary focus: InterventionDescription with nested intervention data."* ticker는 `intervention_description` 개정 이력을 추적하는 로그이지, `gta_evaluation`·`is_in_force`·`date_removed` 같은 필드의 백엔드 정정을 이벤트로 남기지 않는다. `update_period` 필터도 결국 `last_updated`와 같은 개념을 쓰는 것으로 보인다.

- **결론**: GTA API가 제공하는 어떤 필터·엔드포인트(`/data/`의 `update_period`, ticker의 `update_period`/`status`)도 이 부류의 변경을 이벤트로 알려주지 않는다. **전량을 다시 받아 전체 컬럼을 직접 대조하는 것(잠수함 패치 점검)이 유일한 탐지 방법이고, 대체 불가능하다.** 1번 모드(빠른 업데이트)는 이 문제를 풀 방법이 없는 채로 남는 임시 수단이며, "얼마나 자주 2번 모드를 도는가"가 곧 "이런 변경을 얼마나 늦게 알아채는가"를 결정한다.

### E. API 자체가 바뀔 수 있는 것

**E-1. 설명서와 실제 응답이 다름** · 이미 존재

- 스키마는 `implementing_jurisdictions`·`affected_products`·`affected_sectors`를 `string`으로 적어놨으나 **실제는 객체 배열**이다
- 스키마는 `update_period`를 설명하며 "수정 이력이 없으면 `last_updated`는 게시일과 같다"고 하나, 실제로는 `last_updated`가 `date_published`보다 최대 3,605일 **앞선다**
- Quickstart는 응답이 wrapper 없는 bare array라 하고, 스키마에는 paginated wrapper도 정의돼 있다

**문서를 믿고 코드를 짜면 틀린다.** 이 프로그램은 실제 응답 기준으로 짜여 있고, `unpack_response()`가 양쪽 형태를 모두 받는다.

**E-2. 응답 필드 추가·삭제** · 위험 중간

29개 필드를 이름으로 고정해 쓴다. 필드가 사라지면 `flatten()`이 즉시 실패한다(의도된 동작). 필드가 늘면 조용히 무시된다.

- **알아채는 법**: 실패는 바로 보인다. **추가는 안 보인다** — 가끔 응답 키 개수를 확인할 것

### F. 우리 쪽에서 바뀔 수 있는 것

**F-1. BERT 모델 저장소** · 위험 낮지만 치명적

`industrialpolicygroup/industrialpolicy-classifier`의 revision `2cc47b0c…`로 고정돼 있다. 저장소가 비공개로 바뀌거나 삭제되면 **재현이 불가능해진다.**

- **대응**: 모델 파일을 로컬에 별도 보관하는 것을 권한다. 현재는 HuggingFace 캐시에만 있다
- 프로그램은 `id2label`이 `LABEL_0/1/2`가 아니면 즉시 실패하도록 막아뒀다
