## 1. 1순위 — GitHub Actions 이전

### 1-1. 목표 상태

- 주 1회 잠수함 점검(전량) + 일 1회 빠른 업데이트가 GitHub-hosted runner에서 돈다
- 결과: 변경 리포트 → 사이트 자동 배포, 실패 시 이메일 알림, 엑셀은 아티팩트
- PC는 꺼져 있어도 된다. 키·토큰은 GitHub Secrets. 캐시는 외부 객체저장소

### 1-2. 저장소 분리 (첫 작업)

- 새 **비공개** 저장소 1개(예: `skl-economic-security-tracker`)에 `02_웹사이트`의 코드·문서·`reference/`만 넣는다
- 제외: `.venv cache logs output site node_modules .wrangler *.xml .site_users.json` (현 `.gitignore`와 같음)
- 볼트 쪽: 볼트 `.gitignore`에 `04_파생작업/02_웹사이트/`를 추가하고, 같은 경로에 새 저장소를 clone한다(중첩 저장소). Obsidian에서 보는 위치는 그대로
- 연구 문서(`문서/설계_*.md`, 코드북)는 새 저장소에 둔다 — 코드와 같이 움직여야 하는 문서다. 회의록·체크리스트는 볼트에 남는다
- 공개 저장소로 하면 Actions 분이 무제한이지만, GTA 원문·설계 메모가 실리므로 **비공개 유지**. 비공개 Free 플랜은 월 2,000분

### 1-5. 워크플로 2개

- `weekly-full.yml`: 일요일 새벽 `--mode full --yes` → 리포트 → 빌드 → 배포 → 엑셀 아티팩트(보존 14일)
- `daily-quick.yml`: 매일 `--mode incremental --yes` → 리포트 → 빌드 → 배포. 엑셀 생략

### 1-6. 사람 승인 단계의 대체

- 현 설계: 대조 결과를 보고 Y를 눌러야 엑셀 생성. CI에는 사람이 없다
- 대체안: **승인은 "멈춤 조건"으로 치환**한다. 아래에 걸리면 잡이 실패하고 배포·엑셀 생성을 하지 않으며 이메일이 온다
  - 수출통제 9종 중 유형명이 0건이 된 것 있음(이미 큰 경고로 구현됨 → 종료코드로 승격)
  - `intervention_id` 결측·중복, 열 개수 불일치(기존 자동검증 → 종료코드)
  - 전체 표본이 직전 대비 N% 이상 감소(신규 기준. N은 결정 필요, 예 2%)
  - 삭제 건수가 임계치 초과(예 50건)
- 변경 리포트는 GitHub Step Summary에도 그대로 실어 메일·웹에서 바로 읽게 한다
- 통과한 실행은 사람이 나중에 읽는다. 지금도 사이트에 올라간 리포트를 나중에 읽는 구조라 실질적 변화는 없다

## 2. 패널 1 — Distortive Industrial Policy Tracker 고도화

현재: GTA(산업정책 후보 ∧ Red/Amber ∧ 반복공고 접기) × BSV 2021 IPD(고정) × IMF DOTS 총무역 비중·WDI GDP(2026-08-22 정적 CSV).

### 2-1. "GTA + UN Comtrade + 지정학적 거리" 결합안

- **노출 지표를 품목 수준으로**: 지금 버블 크기는 시행국 총무역 대비 비중(DOTS). 조치별 `affected_products`(HS 6단위)와 Comtrade 양자 품목무역을 곱해 "조치가 건드린 무역액"을 만든다. GTA의 trade coverage 방식과 같고, 보고서의 "노출" 서술이 바로 숫자가 된다
  - 호출량: 조치의 (시행국, 피영향국, HS) 조합이 많다 → 연 1회 전량, 월 1회 최근 2년만. R2에 캐시
  - 주의: 2022년 가격 효과(금액 기준), 미러 불일치 — 수입국 신고 기본·수출국 신고 병기(oil_verify와 같은 규칙)
- **거리 지표 자동 갱신**: BSV는 매년 Dataverse에 갱신 → 연 1회 자동 다운로드. 기준연도 2021 고정은 유지하되, 화면에 "최신 연도 기준" 토글을 둬 민감도(41.7% 블록 이동)를 숨기지 않는다
- **빌드 게이트**: 블록 분류가 직전 빌드 대비 N개국 이상 바뀌면 실패(원자료 교체 사고 방지). `bloc_site.build_blocs`와 `build_oil_data.build_blocs_by_iso3`의 일치 diff를 빌드에 상시 포함(10-15 프롬프트 1단계를 자동검증으로 승격)
- **표준 표본 공개**: `canonical_measures.py` 산출 CSV를 `as_of`·SHA와 함께 사이트에서 내려받게 한다. 논문 각주용

### 2-2. 지키는 것

- `D_IP_bert_3==1`은 산업정책 후보군이지 확정 라벨이 아니다 — 화면 문구 유지
- Red/Amber는 외국 상업이익에 해로움이지 환경 분류가 아니다
- count와 share, 분모를 같이 표시

## 3. 패널 2 — 한미 AI 협력 트래커

현재(스크린샷, Notion DB): 열 = 날짜 · 미국 측 주체(다중) · 한국 측 주체 · 주체유형(정부/민간/정부-민간) · 형태(MOU·의향/선언/집행/확정계약) · 분야(AI데이터센터/피지컬AI/통상·규제/파운드리/반도체/AI모델/안보·국방) · 내용 · 규모 · 원문 URL · Drive 원본. 2016년경부터 2026-08까지 누적.

### 3-1. 무엇을 자동화하고 무엇을 하지 않나

- 자동화: (i) 후보 사건 **탐지**, (ii) 입력 **초벌 코딩**, (iii) 검증·집계·시각화·배포
- 자동화하지 않음: (iv) **확정 코딩**. 형태(선언/집행/확정계약)와 분야 판정은 연구자 판단. 모델 결과는 '초안'으로만 표시(04 AGENTS.md "모델 예측을 확정 라벨로 표현하지 않는다")

### 3-2. 구조안

```
[탐지] 보도자료 RSS·뉴스 쿼리 ──▶ [초벌 코딩] LLM → 스키마 JSON
                                        │ 상태=초안
                                        ▼
                            [Notion DB] 모바일 입력·검수  ◀── 연구자 확정
                                        │ 야간 1회 Notion API
                                        ▼
                     [GitHub Action] 검증 → ai_coop.json → ai_coop.html → 배포
```

- Notion을 **입력·검수 UI로 유지**(모바일 입력이 실제로 쓰이고 있음). 저장소 쪽은 읽기만 한다
- 대안: 저장소 내 CSV + GitHub Issue 폼 입력. 외부 서비스 의존이 없지만 모바일 입력이 불편

### 3-3. 스키마 보강(현 열에 추가)

- `id`, `선행 사건`(relation) — 같은 거래의 MOU→확정계약→집행을 잇는다. "선언→집행 전환율"의 근거
- `금액`: 통화·명목/추정·출처 분리. 현재 `규모` 한 칸은 합산 불가
- `주체 정규화`: 기관 마스터 테이블(국적·정부/민간·업종). 엔비디아·NVIDIA 표기 통일
- `출처 등급`: 1차(정부 문서·공시·보도자료) / 2차(언론). `원문 URL` 생존 여부를 야간 검증
- `상태`: 초안/검토/확정 + 검토자·검토일
- `행정부`: 바이든/트럼프2기 (`03_연구확장/20260920_미국_행정부별_트래커_탐색.md`와 연결)
